# Playbook 16: Data Quality & Pipeline Health Report Dashboard

## 1. Objective & Scope

In enterprise BI implementations, business users frequently question data credibility. Building a transparent, dedicated **Data Quality & Pipeline Health** dashboard transforms data validation from an obscure engineering task into a visible business asset.

This playbook details the construction of **Page 5: Data Quality & Pipeline Health**:
1. Executive DQ Scorecard KPIs (`DQ Score %`, `Valid Rows`, `Quarantined Rows`, `Duplicate Rows`).
2. An interactive Defect Pareto Visual analyzing issues by Severity, Entity, and Issue Category.
3. A granular Quarantine Inspection Table allowing operations teams to investigate quarantined records directly in Power BI.

## 3. Step-by-Step Visual Construction

### 3.1: Top KPI Cards (Cards or New Card Visual)
1. **Card 1: DQ Health Score**
   - Measure: `[Data Quality Score %]`
   - Callout Value: Font 32pt, Bold, Accent Green (Hex `#107C41`).
   - Category Label: "Pipeline Health Index".
2. **Card 2: Total Raw Rows Ingested**
   - Measure: `[Total Raw Orders Ingested]` (Display: `502,000`).
3. **Card 3: Valid Production Rows**
   - Measure: `[Valid Orders]` (Display: `499,903`).
4. **Card 4: Quarantined Records**
   - Measure: `[Quarantined Orders]` (Display: `2,097`, Accent Red Hex `#D83B01`).
5. **Card 5: Duplicate Business Keys**
   - Measure: `[Duplicate Orders Count]` (Display: `2,000`).

---

### 3.2: Visual 1: Defect Distribution (Clustered Bar Chart)
1. On **Visualizations** pane, select **Clustered Bar Chart**.
2. Drag `rejected_orders[DataQualityReason]` to **Y-axis**.
3. Drag `[Quarantined Orders]` to **X-axis**.
4. Sort Axis by `[Quarantined Orders]` Descending.
5. Enable **Data labels**.
*Insights Revealed:* Instantly exposes that $95.3\%$ of defects stem from duplicate transaction keys generated by batch synchronization retries, followed by $35$ broken foreign keys and $35$ invalid quantities.

---

### 3.3: Visual 2: Multi-Entity Quality Matrix
1. Select **Matrix visual**.
2. In group **`99_Admin`**, we load query `dq_summary` containing one row per ingested source entity:

```powerquery
// Query: dq_summary (Group: 99_Admin, Enable Load = True)
let
    Source = Table.FromRows({
        {"Orders", 502000, 499903, 2097, 0.9958},
        {"Customers", 25200, 25000, 200, 0.9921},
        {"Inventory", 8400, 8300, 100, 0.9881},
        {"Targets", 417, 415, 2, 0.9952}
    }, {"Source Entity", "Raw Rows", "Valid Rows", "Quarantined Rows", "Quality Score %"}),
    Typed = Table.TransformColumnTypes(Source, {
        {"Source Entity", type text},
        {"Raw Rows", Int64.Type},
        {"Valid Rows", Int64.Type},
        {"Quarantined Rows", Int64.Type},
        {"Quality Score %", Percentage.Type}
    })
in
    Typed
```
3. Drag `dq_summary` fields into the Matrix:
   - Rows: `Source Entity`
   - Values: `Raw Rows`, `Valid Rows`, `Quarantined Rows`, `Quality Score %`.
4. Add conditional formatting Data Bars or Font Color Icons to `Quality Score %`.

---

### 3.4: Visual 3: Operational Quarantine Table
1. Select **Table visual**.
2. Add columns from `rejected_orders`:
   - `order_id` (Business Identifier)
   - `order_datetime` (Transaction Timestamp)
   - `customer_id` (Displays `C9999999` for orphan keys)
   - `product_id` (Displays `P999` for orphan keys)
   - `store_id` (Displays `S999` for orphan keys)
   - `quantity` (Displays `0` or `-1`)
   - `unit_price_egp` (Displays `-10.0`)
   - `DataQualityReason` (Concatenated audit trail)
3. Set column formatting: Highlight invalid values in soft red background.

---

## 4. Interactive Cross-Filtering Workflows

When the data governance officer clicks the bar **"Invalid Customer FK"** in the Pareto Chart:
1. The entire page cross-filters.
2. The Quarantine Table immediately isolates the exact $12$ transactions referencing `C9999999`.
3. The operational team can export these $12$ rows directly to Excel via the visual header (`...` $\rightarrow$ **Export data**) to remediate the PostgreSQL customer master feed.

This completes the closed-loop governance cycle: **Detect $\rightarrow$ Isolate $\rightarrow$ Report $\rightarrow$ Remediate**.
